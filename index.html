Mapping Rules

  • Change Command 主要來自 Test Excel；Baseline 不自行推導。
  • Baseline 只做 Case 1/2/3 規則驗證。
  • Case 3 依 Hierarchy Type + Level + Target 分組；Primary Source 直接在該組 Mapping Review 第一列設定。
  • Primary Source 只能從該組 Sources 選擇；選定後產生 1 Rename + 其餘 Merge，狀態仍為 Pending Review。
  • Accept 後立即套用到 Converted Data。正式 Baseline 比對、Confirmed Mapping Change Log 與 Go Live 確認移至 GO LIVE 流程。
  • Converted Data 手動異動規則：直接編輯階層資料時，系統會依異動類型判斷是否需要產生 Change Command，並在執行前要求使用者確認。
  • Add：若在 Converted Data 輸入原本不存在的新 BG / MD / PD / PDL，系統顯示確認視窗；若 PDL 儲存格以 / 串接多個 PDL，只針對新增加的 PDL 項目產生 Command，不把整個儲存格內容視為一個新 PDL。確認後自動產生 Add {Level} "Name"，寫入該列 Change Command，並在 Mapping Review 建立紀錄且狀態直接為 Valid。
  • Delete：只有 MD 可以 Delete。若清空既有 MD，系統顯示確認視窗；確認後產生 Delete MD "Name"、寫入 Converted Data 的 Change Command，並在 Mapping Review 建立 Valid 紀錄。Delete MD 不代表資料庫實體 DELETE，也不 cascade 刪除其 PD / PDL。
  • PDL 不可 Delete：不再使用的 PDL 應使用 Phase Out；PD / BG 清空也不可自動轉成 Delete。
  • Hierarchy Reassignment：可直接在 Converted Data 調整既有資料的 Parent。例如將 PDL UNO1 從 PD UNO 改到 PD IPC。系統須顯示原 Parent → 新 Parent 的確認資訊；確認後更新 Converted Data、寫入 Change Command，並在 Mapping Review 建立 Valid 紀錄。此異動屬 Merge / Reassignment 語意，不新增獨立 Move Action。
  • Converted Data 亦可用 + Add Hierarchy 新增 BG / MD / PD / PDL；此按鈕本身即為明確的新增操作，建立後直接為 Valid。
  • BG Head、PD Head、MD Head、PG Head、Remark 暫不顯示、不參與 Mapping；Export 時保留原欄位與原值。
